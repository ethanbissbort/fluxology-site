# Repo Audit — August 17, 2026

Third full audit: readiness-focused, covering the marketing site, the three
dashboard sub-sites, all three backend services, the new Office & Mail MCP
servers under `public/office-scout/mcp/`, and the build/CI/deployment layer.
Every finding cites file and line against HEAD `62fb49b`. All five test
suites were executed, the full ship path (`npm run build` including
postbuild) was run, and the built `dist/` was inspected directly.

Method: five parallel subsystem audits (marketing site, dashboard frontends,
backend services, office-scout MCP, infra/CI/docs) plus direct build, test,
and dependency-audit verification, then de-duplication and severity ranking.

**VERIFIED** = the failure was traced or reproduced against the current
tree. **RISK** = structurally plausible, not demonstrated.

## Executive assessment

This is a healthy, actively maintained repository whose one systemic
weakness is now the dominant risk. The backend is the strongest layer:
**380/380 tests pass** across five suites, the MCP connector's auth core
holds (timing-safe compare, secret redaction, real-JWKS hardening tests,
scope isolation), and nearly every infrastructure finding from the
August 8 audit was fixed **with CI guards**. There are **zero
TODO/FIXME/stub/mock markers in production code** anywhere in `src/`,
`services/`, or the dashboards.

The dominant risk is a placement decision: **`public/` is being used as a
working directory for things that are not web content**, and everything in
`public/` ships to the open internet. That one pattern produces the P0
(personal data served as crawlable JSON) and the top P1 (two MCP servers'
source and internal design docs served from the production site). Both were
verified in the built `dist/` output. The newest commit in the repository
(`e219b4d`) is the one that created the larger exposure.

Second theme: **tests that exist but don't gate** — three of five suites
run in no workflow, office-mcp's `npm test` script is itself broken on
Node 22, and nothing type-checks or lints, ever. Third theme: **divergent
duplication** — ~15 copy-pasted functions across the three dashboards where
fixes in one never propagated; the homepage duplicates the product data
file and has drifted; two independently-validated write paths now exist
into the same production Office feed.

## Findings

### P0

**F-01 — Personal data is published on the open web as crawlable static
JSON. VERIFIED.** A residential postal code appears in
`public/deals/data/search-profiles.json:5`, `shipping-calibration.json`,
`seller-watch.json`, `unresolved-listings.json` (8×), and in the live feed
(`listings.json:27-30`). `seller-watch.json` attaches a real person's name
to an eBay handle with negotiation notes; `unresolved-listings.json:14-42`
records purchase behaviour and offer/counter amounts against named sellers.
`public/robots.txt:1-2` allows everything; the `noindex` meta covers HTML
only; no `X-Robots-Tag` exists in any serving config. ~54 KB across six
files is fetched by no frontend code. *Remediation:* move the agent-state
files out of `public/` (the pattern `office-scout/README.md:17` already
prescribes), add Disallow + `X-Robots-Tag` for `/data/`, verify the live
site, decide on a git-history purge for the third-party name.

### P1

**F-02 — Both MCP servers' source, tests, and internal design docs ship to
the public site. VERIFIED in `dist/`:** 49 files / 524 KB including
`docs/SDD-v2.md`, `docs/DESIGN-AUDIT-v1.md`, a 34 KB `.docx`, all
`src/*.mjs`, all 7 test files, and the negotiation playbook
(`outreach.mjs:10-19`). Chain: no `.dockerignore` exclusion (the
`tests`/`*.test.js` patterns at `.dockerignore:74-79` are unanchored/wrong
extension and match nothing) → Astro copies `public/` verbatim →
`Dockerfile:65` → `httpd.conf:113-121` `Require all granted` →
`CADDY-INTEGRATION.md:217` exposes it at `office.fluxology.ca/mcp/…`.
No credentials inside (verified). Introduced by the newest commit.
*Remediation:* move the tree out of `public/` — which also dissolves the
zero-dependency constraint that drove ~430 lines of protocol
re-implementation (F-30).

**F-03 — office-mcp writes the production dashboard with a raw ingest token
and no approval gate. VERIFIED.** `office-mcp/src/dashboard.mjs:146-150`
POSTs upsert with `Bearer OFFICE_INGEST_TOKEN`; `src/tools/index.mjs:490-497`
exposes `office_dashboard_sync{dry_run:false}` with no `verifyAndConsume`
anywhere in the path (unlike the exemplary form-submit and mail-send
gates). The call bypasses the hardened fetcher (no timeout/size cap) and
hand-rolls a second copy of the v2.5 invariants. *Remediation:* gate it, or
route through the fluxology-mcp connector and remove the raw token.

**F-05 — Three of five test suites are run by no CI workflow. VERIFIED.**
dashboard-api's 40-case suite: `mcp-connector-tests.yml:16` *triggers* on
`services/dashboard-api/**` but never runs it. office-mcp and mail-mcp: no
workflow references `public/office-scout/mcp` at all. The Aug 8 finding
"dashboard-api has no tests" was half-fixed: tests written, never wired.

**F-06 — The deals dashboard hides its best qualifying listing and
mis-states shipping resolution. VERIFIED.** `deals/app.js:23` only reads
`landedCadPerLb`, never computes it: `ebay-398236132742`
(`shippingResolved:true`, $62.99 + $42.17 / 18 lb = **$5.84/lb**,
`landedCadPerLb:null`) renders "Unresolved / CURATED" and is excluded from
the HIGH PRIORITY stat and `deal=high` filter (`app.js:25,27,32,33,36`).
Two listings assert `shippingResolved:true` with `shippingCad:null`,
unchallenged. Two listings carry `priceAud` — in neither schema nor app —
and display no price. The schema's proxy-shipping fields
(`schema.json:52-53`) appear nowhere in `app.js`, so the claude.md
proxy-labeling invariant has no rendering mechanism. Same root cause
family as Aug 8 finding #1, surviving in a new form.

**F-07 — CORRECTED (2026-08-17, remediation pass): the AUTH PLAIN payload
was wire-correct all along.** The source line contained **literal NUL
bytes** inside the template string, which render as spaces in every viewer
and make grep treat the file as binary — two independent reviewers read it
as a broken space-separated payload. The real defect is downgraded to P3:
literal control bytes in source are a maintenance hazard and unreviewable.
Fixed by rewriting them as explicit `\u0000` escapes and teaching the test
mock to decode and verify the RFC 4616 separators (it previously accepted
any payload, so neither a regression nor this misreading could ever fail
the suite). SDD §B5 still promises AUTH LOGIN; only PLAIN is attempted.

**F-08 — Email header injection through model-supplied recipients.
VERIFIED.** `eml.mjs:53-54` folds To/Cc without the `headerValue()`
encoding that protects Subject; the schema accepts any string ≥3 chars.
`\r\nBcc:` in a recipient injects headers into the rendered `.eml`.

## Architectural assessment

Sound: the four-container topology with an external edge, consistently
enforced (no host ports, scoped tokens, CI packaging invariants);
dashboard-api as a well-engineered single-writer store; fluxology-mcp as
the reference implementation (canonical schemas at build + drift check,
structured redacted logging, honest-reporting semantics); an evidence-first
commenting culture that records measurements and past bugs.

Three structural problems:

1. **`public/` as a junk drawer** — server source, internal specs, agent
   working state, and archived snapshots all ship. Both top findings share
   this root cause. Fix the boundary, not the instances: `public/` holds
   only what the internet should see, enforced by an Apache deny *and* a CI
   assertion on dist contents.
2. **Divergent copies where shared modules belong** — ~15 duplicated
   functions across three dashboards with measurable fix-drift (abort
   handling, focus restore, focus-ring contrast, storage contracts, id
   normalization: each solved exactly once, each in a different app);
   homepage vs `softwareProducts.ts`; office-mcp's hand-rolled invariants
   vs the canonical schema; `mcp-core` vs the SDK; still five schema
   definitions per feed family.
3. **Invariants enforced at the wrong depth** — server-owned fields,
   null-refusal, and cost-honesty are connector-deep, not store-deep. A
   direct curl with an ingest token bypasses them all, and there are now
   three writers (connector, GitHub sync, office-mcp). dashboard-api should
   own the invariants; writers should be thin.

Extensibility: a fourth dashboard today costs a copied ~700-line app.js, a
sixth schema definition, scope-map/compose/Caddy-doc/workflow edits, and
inherits no fixes. A ~60-line shared module
(`$/esc/safe/safeUrl/asDate/ago/line/toast/bindCards/makeWorkspace`) plus
store-level invariants cuts that to data-plus-config. Once relocated, the
MCP servers should drop `mcp-core`'s 430 hand-rolled lines for the SDK
already pinned in-repo — the zero-dependency constraint only existed
because of the placement mistake.
